# ABA-сервис — Безопасность

Проверка от 22.09.2026, перед публикацией в интернете.
Данные продукта: медицинские данные несовершеннолетних — проверка по строгому уровню.

## Ответ

**Демо с выдуманными детьми публиковать можно** — после двух пунктов из раздела
«Что делаете вы» (около 5 минут).

**Настоящих детей заводить пока нельзя.** Мешают три вещи, все не технические:
хранение данных граждан РК в Казахстане, отсутствие ежедневных копий базы
на бесплатном тарифе и живые демо-аккаунты.

## Что проверено и в порядке

Проверялось не чтением кода, а попытками: запросы к базе от имени каждой роли.

| Проверка | Результат |
|---|---|
| Ключ Claude в коде сайта | Нет. В браузер уходят только публичные значения Supabase |
| Ключи в истории изменений | Нет. `.env.local` закрыт, шаблон `.env.example` без значений |
| Специалист видит чужого ребёнка по прямой ссылке | Нет, база возвращает пусто |
| Специалист меняет чужого ребёнка / заводит своего | Запрещено (403) |
| Специалист начинает занятие с чужим ребёнком | Запрещено (403) |
| Специалист пишет занятие от имени коллеги | Запрещено (403) |
| Специалист повышает себя до руководителя | Не проходит, роль хранится в учётной записи |
| Специалист правит базу навыков, разделы, фей | Запрещено (403), данные не изменились |
| Специалист удаляет занятия | Запрещено |
| Человек без роли (сам зарегистрировался) | Не видит ничего: ни детей, ни занятий, ни навыков |
| Вход в сервис без пароля | Переадресация на страницу входа |
| Заведение сотрудников | Только руководитель; секретный ключ — внутри Supabase, наружу не выходит |
| Проверка вводимых данных | На сервере (zod), склейки SQL нет, чужой текст не выводится как разметка |
| Персональные данные в журналах сервера | Нет |

## Что исправлено в коде

1. Защитные заголовки: сервис нельзя встроить в чужую страницу (`X-Frame-Options: DENY`),
   браузер не угадывает типы файлов, адрес страницы не утекает на посторонние сайты,
   камера, микрофон и геопозиция запрещены.
2. Запрет индексации: `robots.txt`, метка `noindex` на страницах и заголовок `X-Robots-Tag`.
   Сервис не попадёт в поиск Google.
3. Журналы ИИ: при неожиданной ошибке пишется только тип ошибки, без содержимого занятия.

## Что делаете вы

### 🔴 1. Потолок расходов на Claude — до публикации

Зачем: ключ без лимита. Если он утечёт или кто-то из сотрудников нажмёт кнопку
черновика сто раз подряд, счёт вырастет без предупреждения.

1. console.anthropic.com → **Settings → Limits** (или **Billing → Spend limits**).
2. Задайте месячный потолок, например **$10** (≈ 5 000 ₸) — этого хватает на сотни отчётов.
3. Проверка: в разделе видно строку с установленным лимитом.

Там же удалите старый ключ, который заканчивается на `6AAA`, — он был в переписке.

### 🔴 2. Закрыть самостоятельную регистрацию — до публикации

Зачем: сейчас посторонний может завести себе учётную запись. Данных он не увидит,
но на публичной ссылке лишних учётных записей быть не должно.

1. supabase.com/dashboard → проект **aba-service** → **Authentication → Sign In / Providers**.
2. В блоке **Email** выключите **Allow new users to sign up**.
3. Проверка: в браузере адрес `<адрес проекта>/auth/v1/settings` показывает `"disable_signup": true`.

Сотрудников после этого заводит руководитель в самом сервисе — этот путь не затрагивается.

### 🟡 3. Защита от утёкших паролей — на этой неделе

1. Supabase → **Authentication → Policies** (раздел **Password protection**).
2. Включите **Leaked password protection** — Supabase будет сверять пароли с базой
   утёкших и не даст поставить известный.

### ⚪️ 4. До первого настоящего ребёнка

- **Закон РК о персональных данных**: данные граждан РК хранятся на серверах в Казахстане,
  у Supabase такого региона нет. Решение с юристом: либо в сервисе только псевдонимы
  (имя и первая буква фамилии), а полные ФИО — в бумажной карте центра, либо перенос базы
  на казахстанский сервер (ps.kz, Казахтелеком), ~15 000–30 000 ₸ в месяц.
- **Ежедневные копии базы**: на бесплатном тарифе их нет. Supabase Pro — $25 (≈ 13 000 ₸)
  в месяц, включается одной кнопкой.
- **Демо-аккаунты** `rukovoditel@example.com`, `aruzhan@example.com`, `dana@example.com`
  и выдуманных детей удалить.
- **ИИ получает имя и возраст ребёнка** (без фамилии). Anthropic по умолчанию не обучает
  модели на данных API. Если центр захочет строже — отправляем только инициалы,
  правка на пять минут.
- **Одна база для разработки и публичной версии**. Позже стоит развести: отдельный
  проект Supabase для боевой версии.

## Что проверить после публикации

- Адрес открывается по `https`, замочек в браузере есть.
- Без входа ни одна страница не открывается.
- Специалист видит только своих детей.
- В поиске Google сервис не появляется (проверка через неделю: `site:<адрес>`).
