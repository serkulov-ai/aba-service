## 3. Юридическое ограничение

Закон РК «О персональных данных и их защите» требует хранить персональные данные
граждан РК на серверах в Казахстане. У Supabase таких серверов нет.

- Тестирование — только на выдуманных детях.
- До запуска с настоящими детьми центр с юристом выбирает:
  1. в Supabase — только псевдоним (имя + первая буква фамилии), полные ФИО — в бумажной карте центра;
  2. или перенос базы (PostgreSQL) на казахстанский сервер (PS Cloud, Казахтелеком), ~15 000–30 000 ₸/мес. Код не переписывается.

Подробно — в SECURITY.md (шаг 3).

## 6. База данных (Supabase, проект aba-service)

| Таблица | Что хранит |
|---|---|
| profiles | Сотрудники: имя, роль (руководитель / специалист). Роль ставится только сервером |
| assistants | Феи — выбираются на занятии, в сервис не входят |
| children | Дети: ФИО, дата рождения, методики, специалист |
| skill_domains, skills | База навыков VB-MAPP центра: разделы, навыки по порядку, инструкции, комментарий куратора |
| child_targets | Программа ребёнка: цели, стимулы А/Б/В, статус, текущая задержка |
| lessons | Занятия: кто вёл, фея, был ли родитель, заметки, отчёт родителям |
| target_sessions | Сессии по цели: 9 проб (S/P/M), задержка, проценты |
| target_events | История: смена задержки, освоение — по совету сервиса или решение специалиста |

Правила доступа (RLS) проверены на демо-аккаунтах: руководитель видит всех детей,
специалист — только своих, человек без роли — ничего. Миграция: `supabase/migrations/`.

Проверки: `npm test` — правила методики на примерах с бланков (17 проверок: строки
чек-листа, все 27 клеток таблиц ротации, переходы задержек, освоение).

## 7. Как работает занятие без интернета

Отметки, смена задержки и освоение сначала пишутся в память браузера (IndexedDB,
`src/lib/offline/`), потом по порядку уходят в базу. У каждой записи свой id,
поэтому повторная отправка ничего не задваивает. Незаконченная сессия хранится
как черновик и переживает перезагрузку страницы.

Ограничение: сама страница должна быть открыта, пока есть связь. Открыть сервис
с нуля без интернета нельзя — для этого нужен режим приложения (PWA), он в Части 5.

## 8. ИИ-черновики

`src/lib/ai/lesson-report.ts` — только сервер. Модель `claude-sonnet-5`, ответ строго в форме
двух полей (structured outputs + zod), effort `medium`, таймаут 60 сек. Модели уходят имя ребёнка
(без фамилии), возраст, результаты проб и заметки специалиста. Ошибка ИИ не ломает занятие:
специалист пишет отчёт сам. Ключ — `ANTHROPIC_API_KEY` в `.env.local`.

## 9. Учётные записи сотрудников

Заводит их руководитель прямо в сервисе. Пароль сервис придумывает сам и показывает
один раз. Создание, сброс пароля и отключение доступа выполняет серверная функция
Supabase `staff-admin` (`supabase/functions/staff-admin/`): секретный ключ есть только
внутри неё и на сайт не попадает. Функция проверяет, что вызвавший — руководитель.

Роль хранится в `app_metadata` учётной записи, её нельзя поменять из браузера.
Карточка сотрудника создаётся триггером при создании учётной записи и при изменении
метаданных (Supabase делает это двумя шагами).

## 10. Режим приложения (PWA)

`src/app/manifest.ts` + значки в `public/` — сервис ставится на домашний экран и
открывается без адресной строки. `public/sw.js` хранит оболочку приложения и при потере
связи показывает экран `/offline` вместо ошибки браузера. Страницы с данными детей
не кэшируются: на общем телефоне чужие данные не должны оставаться в памяти.
Сохранение оболочки включается только в собранной версии (`npm run build && npm start`).

## 11. Что решили НЕ делать в первой версии

- Вход для родителей (второй этап, после отчётов через WhatsApp).
- Запись на занятия, расписание, оплаты.
- Автоматический подбор программы ИИ — сервис предлагает следующую цель по иерархии, решает человек.
- Казахский язык.
- Ротация: таблицы 1 → 2 → 3 идут по кругу по числу сессий цели (второй круг в том же занятии — следующая таблица). Подтвердить у Аружан.
